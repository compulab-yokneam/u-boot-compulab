CompuLab i.MX8MP on NXP U-Boot 2026.04
=====================================

This port carries the CompuLab i.MX8MP support from
``u-boot-compulab_v2023.04-d1d8_d2d4-devel`` onto NXP's ``lf_v2026.04``.
It keeps the board-specific hardware description, environment, EEPROM
identification and firmware rather than substituting the NXP EVK configuration.

Supported configurations
------------------------

The standard boot configurations share ``compulab-imx8mp_defconfig``.
Select exactly one lowercase target fragment:

* ``ucm-imx8m-plus.config``
* ``ucm-imx8m-plus-sbev.config``
* ``mcm-imx8m-plus.config``
* ``mcm-imx8pv2.config``
* ``som-imx8m-plus.config``
* ``iot-gate-imx8plus.config``
* ``iotdin-imx8p.config``
* ``iot-gate-imx8pv2.config``

Each fragment preserves its target's existing drivers, boot command, RTC,
display and other board-specific settings. The SBEV fragment selects the
UCM target with ``CONFIG_SBEV_UCMIMX8PLUS=y``.

Falcon boot retains its standalone configurations:

* ``ucm-imx8m-plus_falcon_defconfig``
* ``iot-gate-imx8plus_falcon_defconfig``
* ``iotdin-imx8p_falcon_defconfig``

The common defconfig enables all D1/D2/D4/D8 compact LPDDR4 timing subsets
and the experimental MRR identification probe, including probing when the
EEPROM already contains a valid identification. EEPROM updates are verified.
The raw timing sources and the packer remain available under
``board/compulab/plat/imx8mp/ddr/``. The expanded timing layout supplied to
TF-A remains unchanged. With the NXP 2026.04 driver, trained CSR values are
captured in controller initialization after the PHY finishes, and are not
saved during the identification-only MRR pass.

Board support includes the existing Ethernet/PHY setup, MMC, USB, SPI/I2C,
TPM device descriptions, environment and capsule handling. The MCM-iMX8Pv2
carrier board retains its micro-SD support, USB roles and HDMI/LVDS/MIPI
boot displays, including the LVDS default and HDMI shutdown before Linux.
Availability of each interface depends on the selected board configuration.

Build
-----

Use a separate output directory. For example::

    make O=build-mcm ARCH=arm CROSS_COMPILE=aarch64-linux-gnu- \
        compulab-imx8mp_defconfig mcm-imx8pv2.config
    make O=build-mcm ARCH=arm CROSS_COMPILE=aarch64-linux-gnu- -j8 flash.bin

Replace ``mcm-imx8pv2.config`` with the required target fragment. The
common defconfig intentionally selects no target. Its first target fragment
is merged into the raw common settings before Kconfig resolves the complete
configuration, preserving the settings that depend on board selection.
Apply the target fragment before any capacity or feature fragments. Later
fragments use the normal resolved-configuration merge path. This also works
with ``make -j8`` and when the target fragment is applied by a separate
``make`` invocation. To change targets, reapply the common defconfig and
the new target fragment.

The firmware helper extracts the bundled BL31, OP-TEE and 202006 LPDDR4
training firmware into the output directory. The NXP
``imx8mp-u-boot.dtsi`` binman description packages these files with SPL and
U-Boot into ``flash.bin``; no CompuLab-specific binman description is
required. Firmware already supplied in the output directory can be used
in place of the bundled files.

The common defconfig already includes the final settings obtained by merging
``d0.config d1.config d2.config d4.config d8.config lpddr_mrr_probe.config``.
Those fragments do not need to be added to the normal build command.
The four DRAM subsets and both ``COMPULAB_LPDDR4_MRR_PROBE`` and
``COMPULAB_LPDDR4_MRR_PROBE_ALWAYS`` are enabled by default.

To restrict the timing subsets, merge a capacity fragment after the target.
For example, to retain only D2/D4::

    make O=build-mcm ARCH=arm CROSS_COMPILE=aarch64-linux-gnu- \
        compulab-imx8mp_defconfig mcm-imx8pv2.config d2d4.config
    make O=build-mcm ARCH=arm CROSS_COMPILE=aarch64-linux-gnu- -j8 flash.bin

Do not reuse a configured 2023.04 output directory. The port uses the
2026.04 SPL configuration names and device-tree ``bootph-*`` annotations.
The Falcon configurations use ``CONFIG_SPL_PAYLOAD_ARGS_ADDR`` for the
kernel arguments/device-tree load address.

HAB
---

The inherited NXP binman description wraps SPL and FIT in
``nxp-imx8mcst`` entries when ``CONFIG_IMX_HAB`` is enabled. That build path
invokes CST and needs its executable, SRK table, certificates and private
keys. Follow ``doc/imx/habv4/guides/mx8m_spl_secure_boot.txt`` for the
signing tool configuration. The old external-FIT post-processing procedure
is not interchangeable with this layout.

HAB signing and the compatibility of the existing SPL authentication hooks
and configuration options require separate validation. In particular,
``CONFIG_IMX_SPL_FIT_FDT_SIGNATURE`` selects a legacy, separate FIT-header
signature path and must not be assumed compatible with NXP's embedded-FIT
CST layout. Unsigned build validation does not establish secure-boot support.
Private keys and signed production images are not included in this port.

Validation
----------

The common defconfig plus each of the eight target fragments resolves to
the same Kconfig settings as its former standalone defconfig merged with
all four DRAM subsets and the MRR probe fragment. All eight combinations
build ``flash.bin``. The three Falcon defconfigs are unchanged by this split.

Check the sequential defconfig/fragment workflow with::

    python3 test/compulab/test_config_fragments.py

Cross-compilation with GCC 13 completed for all eleven configurations,
including their ``flash.bin`` images, during the initial port. The compact
DRAM subsets and MRR probe were also built during the port.
Earlier HAB-enabled compilation used the former CompuLab binman layout
and does not validate CST signing with the inherited NXP layout.
The unmodified NXP i.MX8MP EVK configuration built U-Boot and SPL with
CompuLab support disabled. The bundled firmware matches the source branch.

Host-side DDR checks can be run with::

    python3 board/compulab/plat/imx8mp/ddr/pack.py --check
    python3 test/compulab/test_ddr_compact.py
    python3 test/compulab/test_ddr_compact_phy.py

These verify the generated compact tables, register traces, expanded saved
timing layout and PHY identification/training paths. Cross-compilation
checks do not replace hardware validation. Cold/warm boot, every required
DRAM population, storage, Ethernet, USB, display handoff and Falcon boot
need testing on their respective boards. A HAB-enabled image also requires
signing and authentication testing on the target.
